# PRD: 可配置对话服务连通性与助手初始化

## Problem

AI 创作助手通过用户在系统偏好设置中保存的对话地址、密钥和模型发起 SSE 请求。当前失败时统一显示 `Failed to fetch` 的泛化提示：用户无法区分地址、密钥、服务端 HTTP 错误、浏览器 CORS 限制和桌面端 CSP 限制。与此同时，设置页面允许自定义地址，而桌面端 CSP 仅允许一组固定域名，形成配置可保存但无法使用的矛盾。

首次打开 AI 创作助手及用户点击“新建对话”时也不会自动向模型发送项目创作上下文；只有用户主动发送消息或生成草稿时，项目名称、简介和当前正文才会进入请求。

## Goals

- R1: 对话服务请求失败时，向用户区分 HTTP 状态错误与本地传输/CORS/CSP 错误；不得显示 API Key 或完整请求体。
- R2: 桌面端允许系统偏好设置中保存的 HTTPS 自定义对话服务地址参与连接，不因静态 CSP 域名白名单直接被拦截。
- R3: 首次打开助手和点击“新建对话”时，自动发起一轮基于当前项目上下文及回填目标的初始化对话。
- R4: 初始化请求不得发送任何 API Key、服务地址或其他连接配置给模型；仅发送当前项目的创作数据、回填目标及对话指令。
- R5: 已有的手动输入、图片附件、SSE 停止、项目级消息持久化、候选草稿确认回填保持可用。

## Acceptance Criteria

- AC1: 对话 API 返回 401、403、404、429 或 5xx 时，助手展示对应的 HTTP 状态和可操作的中文说明。
- AC2: `fetch` 在没有 HTTP 响应前失败时，助手说明这通常由网络、CORS 或桌面 CSP 导致，并显示不含路径和密钥的服务主机名。
- AC3: 打开空会话后，助手自动生成一条针对项目上下文与目标的首轮回复；新建对话后同样发生。
- AC4: 自动初始化完成前禁止并发发送和生成草稿；关闭侧边栏会中止该请求。
- AC5: 自动初始化的请求包含项目上下文，且不包含连接配置字段。

## Non-goals

- 不对用户已保存的密钥或地址执行未经确认的真实模型调用来做自动探测。
- 不实现浏览器模式绕过第三方服务的 CORS；该模式仍需要服务端允许 `http://127.0.0.1:1420`，或通过未来明确授权的本地代理运行。
- 不新增联网搜索、模型工具调用或更改表单回填格式。

## Assumptions

- 用户正在 `develop` 分支的现有脏工作区中继续开发；本任务只触及对话配置、SSE 助手及其测试。
- 当前桌面端首先通过 CSP 放宽修复自定义 HTTPS 地址；完整的 native HTTP 转发不属于本次最小修复。

## Validation Contract

- 静态检查确认 CSP 与失败分类路径。
- 单元测试覆盖 HTTP 状态错误、传输错误以及首次/新建会话初始化。
- 构建验证 TypeScript 与前端打包。
- 真实已认证模型请求由用户在本地配置后手动验证，状态为 `unverified`，不会在自动测试中使用真实密钥。
