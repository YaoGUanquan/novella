# Novella 创作助手项目记忆与需求澄清

## Problem

Novella 已有项目级 SSE 创作助手，但每次对话只携带原始项目上下文和聊天记录，缺少对“用户意图、已确认事实、待确认问题、项目术语”的稳定表达。外部 `mattpocock/skills` 是开发代理工作流，不作为产品运行时依赖；本需求只借鉴其需求访谈和共享词汇思想。

## Outcome

让用户可以在脚本、角色和分镜表单旁通过同一个侧边助手进行多轮澄清。模型返回的结构化状态先作为本轮草稿展示，用户明确确认后才写入当前项目的本地记忆；新建对话仍自动携带已确认记忆。

## Requirements

- R1. 每次普通对话请求包含当前表单目标、最新项目上下文、已保存项目记忆和“先澄清再建议”的创作 intake 规则。
- R2. 模型可在自然语言回复末尾返回受约束的结构化状态：意图、已确认事实、待确认问题和项目术语；状态标记不应污染用户可见正文或候选稿解析。
- R3. 本轮状态必须先展示给用户；只有点击“保存本轮记忆”后，才合并到当前 `projectId` 的本地记忆。
- R4. 新建对话清空消息和候选稿，但保留同一项目的已确认记忆；切换项目时读取对应记忆。
- R5. 用户可以清除当前项目记忆；清除不影响项目正文、表单值、聊天记录和已保存工程。
- R6. 现有候选稿仍必须经过解析和确认弹窗后才调用 `onApply`；普通聊天不得自动回填表单。

## Non-goals

- 不安装或执行外部 `SKILL.md`，不新增开发代理运行时。
- 不新增远程 API、模型供应商、密钥存储或联网搜索能力。
- 不把未确认的模型推测自动写入项目数据。
- 不改变现有项目保存、角色/分镜解析和图片附件协议。

## Acceptance

- 聚焦组件测试覆盖：状态标记解析/隐藏、记忆确认保存、清除记忆、新建对话保留记忆、候选稿仍需确认回填。
- `pnpm exec tsc --noEmit` 和现有创作助手测试通过。
- 构建验证只说明前端静态结果；真实模型、CORS、Tauri 安全存储和联网能力保持未验证。

## Decisions

- 采用 Novella 自有 prompt/state contract，不复制外部技能文件。
- 记忆按项目存储在现有前端本地存储边界内，保存前由用户确认。
- 结构化状态使用仅供产品解析的 `<novella-state>...</novella-state>` 标记；候选稿请求关闭该标记，保持既有 JSON/文本解析契约。
