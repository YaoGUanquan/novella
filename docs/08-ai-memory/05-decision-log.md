## 2026-08-22：设置页只暴露对话、图片、视频三个连接面

- 决策：用户配置入口收敛为三类服务连接；对话策略按模型内部选择；图片/视频生成优先走已保存连接。
- 背景：旧设置暴露内部 Provider 协议和未被生成入口消费的字段。
- 影响：`SettingsPage` 与 `ai-connection-settings.ts` 成为连接真相；旧 per-provider 卡不再作为产品表面。
- 重新评估：需要按供应商拆分高级参数、或图片也改为异步任务协议时。

## 2026-08-22：助手对话框提高对比度，服饰卡用浅色字

- 决策：候选稿摘要卡、助手气泡、思考过程使用更深一层底色和白色/浅灰文字；用户气泡保持白底深字。
- 背景：服饰条目在深蓝底上用暗灰字，标题和类型几乎不可读。
- 影响：只改展示层 class，不改回填数据。
- 重新评估：侧栏改成浅色主题时。

## 2026-08-22：外观字段合并进表单，字符串 JSON 不得当聊天气泡

- 决策：解析时把顶层 height/bodyType/features 与 appearance 合并；thin→slim；厘米身高用输入框；中文颜色映射色块。思考过程下的字符串化 JSON 隐藏，提示去下方候选稿核对。
- 背景：外观页身高/体型/特征空白，色块全黑；模型把角色数组包成 JSON 字符串后，气泡按普通正文显示。
- 影响：角色草稿解析与 CharacterDesigner 水合；脚本/分镜 JSON 形状不变。
- 重新评估：身高是否统一改为厘米输入，不再保留 矮/中等/高 枚举。

## 2026-08-22：候选稿默认给人看中文摘要，JSON 收到「查看原文」

- 决策：解析成功的候选稿用与表单对齐的中文标签展示；原始 JSON 折叠；复制仍用原文。未解析仍显示原文。
- 背景：回填卡片把整段 JSON 放在主视图，普通用户无法核对姓名、外观、服饰。
- 影响：只改展示，不改回填/保存。脚本/分镜共用同一摘要。
- 重新评估：生成草稿时聊天气泡里若仍出现 JSON，是否要从流式正文里隐藏。

## 2026-08-22：角色草稿先回填表单，对话内保存才写入项目

- 决策：角色候选稿解析成功后先回填左侧可编辑草稿（含外观、服饰）；对话里点「保存角色」才写入已确认角色。项目记忆保存不等于角色表单已填。
- 背景：用户确认「牛来」并保存记忆后，创建角色表单仍为空；旧流程要另点生成草稿和填充表单，且解析丢外观/服饰。
- 影响：覆盖助手面板旧 R3/R4 对「角色草稿预览」的禁止自动改表单；已确认角色仍需保存点击。脚本/分镜默认路径不变。
- 重新评估：脚本/分镜是否采用同一套预览+对话保存，或真实模型不主动 propose-candidate 时。

## 2026-08-22：多选技能保留各结果，文末只问一件事

- 决策：用户点选多个可见技能时，助手仍输出各技能正文；禁止技能内并列「最小下一步」；全文最后只出现一次「本轮结论」和互斥选项。
- 背景：想法发散与文案润色被拼进同一轮，各写一套请确认，用户无法回答。
- 影响：只改提示合同，不升级为可执行技能，不做可点选项。
- 重新评估：需要可点击下一步，或真实模型长期不遵守收口时。

## 2026-08-22：思考过程使用 Cursor 式可折叠轨迹

- 决策：智能体步骤在生成中展开并显示「正在思考」；结束后折叠为一行「思考过程」，用图标表示状态，不再用「完成 · 步骤名」编号列表混进正文。
- 背景：功能时间线已接入，但截图里用户仍只看到最终文案，认为思考过程没有设计出来。
- 影响：只改展示层；步骤语义仍是编排动作，不是模型思维链，也不是真实工具循环。
- 重新评估：步骤变长、出现真实工具调用，或用户要求始终展开时。

## 2026-08-22：创作助手「思考过程」指智能体编排步骤

- 决策：用户可见的「思考过程」改为智能体本轮编排时间线（开始处理、应用点选技能、请求对话模型、整理回复、失败/取消），不是供应商推理分片，也不是模型输出的伪思维链。发送后清除输入框技能标签；无可见正文时保留步骤和说明。
- 背景：用户明确纠正先前实现；旧需求把思考定义成 `thinking`/`reasoning_content`，多数模型不发该分片，界面只剩「AI 正在输入...」或空白卡片。
- 影响：覆盖 `creative-assistant-skills-and-thinking` 的 R7/R8/D4 用户可见语义；不升级为可执行 Agent 运行时；AE 技能仍只做提示词转向。
- 重新评估：助手具备真实工具循环、需要把工具调用挂到同一时间线，或用户要求重新展示模型推理时。

## 2026-08-22：创作助手技能来源分层

- 决策：下拉不再展示 Novella 产品技能（澄清需求、生成草稿、记忆提案）；这三项作为智能体默认能力始终启用。用户可选技能改为 AE 仓库创作向适配（想法发散、结构化整理、文案润色、画面提示词、质量审查），只注入 Novella 自写指令，不执行、不拷贝 `SKILL.md`。当前下拉三项从来就不是 `mattpocock/skills` 文件。
- 背景：用户要求隐藏误认为 mattpocock 的技能，并把可选技能改到 `YaoGUanquan/codex-ai-agent-engine`；AE 技能面向 Codex 开发代理且上游 GPL，不能作为终端用户运行时。
- 影响：注册表增加 `visibility` 与 AE 目录钉扎；点选才启用 AE 适配技能；写表单/记忆仍需确认。远程对照上游全量目录留后续脚本。
- 重新评估：需要自动 diff 上游技能、模型自选 AE 技能，或把编码类 AE 技能引入产品时。

## 2026-08-22：以静态证据建立项目基线

- 决策：先初始化 AE 目录和长期记忆，再开始外部 AI 接口开发。
- 背景：仓库包含多个前端、Rust 和媒体边界；外部文档不能替代本地代码证据。
- 影响：后续功能变更必须更新 `docs/03-analysis` 或相关记忆条目，并保留验证命令和未验证项。
- 重新评估：架构边界发生变化、引入新的远程服务或首次完成桌面端运行验证时。

## 2026-08-22：外部 API 接入暂不固化供应商

- 决策：在用户确认具体模型/视频厂商、endpoint、认证和代理模式前，不创建具体 Provider 实现。
- 背景：这些选择会改变 API、密钥存储、异步任务模型、错误处理和验证范围。
- 影响：当前记忆只记录可复用的扩展边界，不记录猜测性的 endpoint 或模型能力。
- 重新评估：首个供应商和请求契约确认后。

## 2026-08-22：产品内助手采用 Novella 自有创作记忆协议

- 决策：不在用户侧运行或注入 `mattpocock/skills` 的开发代理技能；借鉴其需求澄清和共享词汇思想，在 `src/features/creative-assistant` 内维护项目级、用户确认后的创作记忆。
- 背景：外部技能面向代码代理，不是漫剧创作运行时；直接注入会增加无关上下文、提示词漂移和第三方文件维护风险。
- 影响：普通对话使用 `novella-state` 状态标记提出意图、事实、约束、待确认问题和术语；只有用户点击保存本轮记忆后才写入项目本地存储。候选稿请求关闭该协议并继续走现有确认回填。
- 重新评估：需要服务端持久化、多人协作记忆、联网工具调用，或项目知识图谱成为正式领域能力时。

## 2026-08-22：对话服务采用开发代理与生产原生传输的双轨策略

- 决策：开发期允许通过受限的 Vite 本地代理解决已配置对话服务的 CORS 预检问题；打包交付时不依赖 Vite 或 `127.0.0.1`，后续以 Tauri/Rust 原生 HTTP/SSE transport 作为根治方案。
- 背景：浏览器从 `http://127.0.0.1:1420` 直连远端服务时，已观察到 `OPTIONS` 预检被拒绝，导致实际 SSE 请求未发出。Codex 的网络请求不受浏览器同源策略约束，不能作为 WebView 可直连的证据。
- 影响：开发代理只能转发到启动时明确指定的 HTTPS 上游，页面不得控制代理目标；生产 transport 需要独立覆盖请求验证、超时、取消、事件清理、脱敏日志和真实服务契约测试。
- 重新评估：Tauri 原生 transport 完成并通过桌面端 SSE 验收后，或产品改为由本地 HTTP 服务承载前端时。

## 2026-08-22：桌面端切换到受控 Rust SSE，助手提供恢复操作

- 决策：Tauri runtime 优先调用 Rust `start_configured_dialogue`/`cancel_configured_dialogue`，通过 `novella://dialogue/*` 事件返回文本分片、完成和脱敏错误；Web runtime 保留 Vite 代理或直连。助手增加失败重试、单条消息删除和清空当前会话。
- 背景：浏览器 CORS 无法由打包应用中的 Vite 服务器解决；失败后用户需要在不丢失项目记忆的情况下恢复当前对话。
- 影响：桌面端需要 `reqwest` Rust 依赖和 IPC 事件契约；API key 只进入 native 请求内存，不写日志或事件。2026-08-22 已在本机完成 Rust 编译检查和 `pnpm tauri dev` 启动；真实密钥桌面 SSE 仍待用户在 Tauri 窗口验收。
- 重新评估：需要上传图片的 native multipart、视频/图像原生传输、重试策略扩展为指数退避，或远端供应商 SSE 契约发生变化时。

## 2026-08-22：新建工程 AI 灵感采用 feature 适配与本地兜底

- 决策：新建工程的“随机灵感”优先调用已配置对话 SSE；shared 表单通过回调注入，不直接依赖 core service；模型失败、取消或非法 JSON 时回退本地样本。
- 背景：创建工程前尚无项目级助手会话，但用户希望模型理解当前标题、概要、画风和画幅；同时创建流程不能依赖外部服务可用性。
- 影响：`ProjectData` 保存 `artStyle` 和 `aspectRatio`；四类助手复用这些上下文；真实密钥不进入请求消息或测试。
- 重新评估：需要持久化创建页会话、多人共享灵感、联网搜索或图片参考输入时。

## 2026-08-22：创作助手采用注册表技能与思考分流

- 决策：在现有侧边对话上增加可启用/点选的内置技能注册表，以及 thinking/text 双轨流；写技能只产生提案，确认后才回填或保存记忆。不加载外部 SKILL.md，不合并 Auto-Swarm。
- 背景：用户选择方案 B；当前 SSE 只产出扁平文本，无法展示思考或可见调用。
- 影响：`streamConfiguredDialogue` 仍只转发 text 分片；助手改走 `streamConfiguredDialogueEvents`。技能标记为 `<novella-skill id="...">`。桌面 chunk 事件增加 `kind`。
- 重新评估：需要跨会话记住禁用技能、原生 function calling、嵌套子智能体或文件技能包时。
