## 2026-08-23：生成图片转为项目相对资产，预览经受控 IPC 恢复

- 决策：桌面端把图片供应商的 JSON/SSE/Base64 结果落盘到 `<workingDir>/<projectId>/assets/images/`，角色和助手会话只保存 `assets/images/...`；预览通过 `read_image_asset` 校验并读取为 Blob URL。保存既有项目以路由 ID 为准，加载器拒绝跨项目 store fallback 和陈旧磁盘快照覆盖。
- 背景：供应商 API 已成功返回图片，但 UI 只显示“生成失败”或重载后为 0 张；根因同时包含 Grok SSE/Data URL 契约、保存时随机 UUID、跨项目 fallback 和异步水合竞态。
- 影响：configured image service、Tauri 图片命令、角色参考图、助手图片消息、项目保存/加载和工作目录设置统一遵循 canonical 相对路径合同。
- 何时重新评估：项目资产迁移到内容寻址存储/云同步，Tauri 提供更窄的正式 asset scope，或图片供应商统一为异步任务协议时。

## 2026-08-23：创作助手确定性 UI 状态由 feature 纯 reducer 统一管理

- 决策：消息、活动 turn、错误、候选稿、项目记忆、hydrate/reset 和外部图片消息统一进入 `src/features/creative-assistant/creative-assistant-ui-reducer.ts`。core Agent 保持 UI-free；输入、附件、弹窗、DOM、取消、网络和持久化 effect 留在 React 组件。
- 背景：多个独立 setter 在流式完成、失败、取消、候选解析和图片生成之间形成 split-brain，旧请求 finally 可能清掉新请求状态。
- 影响：终态 action 携带 `assistantId` 并原子收尾；完成回调结束前保持 generating；项目记忆与候选确认语义、持久化格式和视觉基线不变。
- 何时重新评估：多个页面需要共享同一实时助手实例，或 Agent 事件消费需要独立可复用 hook 时；仍不默认迁移到全局 Zustand。

## 2026-08-23：策划页图片生成看已确认角色，重启后从工程文件回填

- 决策：助手回填只写草稿；「生成参考图」只看工程已确认 `characters`。重启后不得用无角色的 Zustand 列表挡住工程文件；保存时把确认角色同步进列表。
- 背景：重启后再进策划页，待确认草稿还在，图片生成区消失，必须再点「确认并保存」。
- 影响：`useProjectLoader` 继续读文件并合并角色；水合 key 包含角色数量；`saveProject` 同步 Zustand。
- 重新评估：若确认角色改成只存在工程文件、不再进项目列表，可去掉列表同步。

## 2026-08-22：设置页只暴露对话、图片、视频三个连接面

- 决策：用户配置入口收敛为三类服务连接；对话策略按模型内部选择；图片/视频生成优先走已保存连接。
- 背景：旧设置暴露内部 Provider 协议和未被生成入口消费的字段。
- 影响：`SettingsPage` 与 `ai-connection-settings.ts` 成为连接真相；旧 per-provider 卡不再作为产品表面。
- 重新评估：需要按供应商拆分高级参数、或图片也改为异步任务协议时。

## 2026-08-22：助手对话框提高对比度，服饰卡用浅色字

- 决策：候选稿摘要卡、助手气泡、思考过程使用更深一层底色和白色/浅灰文字；用户气泡保持白底深字。
- 背景：服饰条目在深蓝底上用暗灰字，标题和类型几乎不可读。
- 影响：只改展示层 class，不改回填数据。
- 重新评估：侧栏改成浅色主题时。

## 2026-08-22：外观字段合并进表单，字符串 JSON 不得当聊天气泡

- 决策：解析时把顶层 height/bodyType/features 与 appearance 合并；thin→slim；厘米身高用输入框；中文颜色映射色块。思考过程下的字符串化 JSON 隐藏，提示去下方候选稿核对。
- 背景：外观页身高/体型/特征空白，色块全黑；模型把角色数组包成 JSON 字符串后，气泡按普通正文显示。
- 影响：角色草稿解析与 CharacterDesigner 水合；脚本/分镜 JSON 形状不变。
- 重新评估：身高是否统一改为厘米输入，不再保留 矮/中等/高 枚举。

## 2026-08-22：候选稿默认给人看中文摘要，JSON 收到「查看原文」

- 决策：解析成功的候选稿用与表单对齐的中文标签展示；原始 JSON 折叠；复制仍用原文。未解析仍显示原文。
- 背景：回填卡片把整段 JSON 放在主视图，普通用户无法核对姓名、外观、服饰。
- 影响：只改展示，不改回填/保存。脚本/分镜共用同一摘要。
- 重新评估：生成草稿时聊天气泡里若仍出现 JSON，是否要从流式正文里隐藏。

## 2026-08-23：桌面端图片生成走原生 HTTPS，避免浏览器 CORS

- 决策：Tauri 下配置的图片服务通过 Rust `generate_configured_image` 直连；Web 仍用 fetch。地址补 `/v1/images/generations`，尺寸 `2K` 转成 `1024x1024`。
- 背景：用户在 sub2api 控制台测 Grok Imagine 成功，Novella 却报 Failed to fetch。对话已有原生通道，图片仍走 WebView fetch，会被跨域拦住。
- 影响：桌面端图片请求不再经过浏览器 CORS；图片地址必须是 HTTPS。
- 重新评估：需要支持 HTTP 内网 sub2api，或图片也走 Vite 开发代理时。

## 2026-08-23：参考图 Failed to fetch 解释为连不上图片服务

- 决策：无 HTTP 状态的 `Failed to fetch` / `Network Error` 映射为「连不上图片生成服务」，不把英文原文丢给 toast。
- 背景：角色已保存成功后点生成参考图，用户看到「角色参考图生成失败：Failed to fetch」，误以为是角色或第三方业务拒绝。
- 影响：只改图片错误文案；401/5xx 仍按第三方服务解释。
- 重新评估：桌面端需要区分 CORS、代理未启动和 DNS 失败时。

## 2026-08-23：策划候选稿截断时抢救已完成的大纲和角色

- 决策：`parsePlanningDrafts` 不再把 `JSON.parse` 的英文语法错误直接丢给用户；截断时抽出完整 `outline` 和已闭合的角色对象，未写完的角色丢弃。
- 背景：模型常在最后一个角色的颜色字段截断，旧逻辑用最后一个 `}` 硬切，整段候选稿作废。
- 影响：只改策划稿解析与助手错误文案；分镜/脚本解析暂不改。
- 重新评估：需要同样抢救脚本/分镜 JSON，或模型改为流式分片对象时。

## 2026-08-23：项目记忆卡强制深底浅字，禁止半透明靛蓝叠灰字

- 决策：项目记忆与字段标签/值使用成套表面 token：`!bg-slate-800` + `!text-white`，标签用 `!text-slate-300`，不再用 `bg-indigo-500/5` 或 `opacity-70` 降对比度。
- 背景：用户截图显示项目记忆正文几乎看不见；半透明底加灰字再叠透明度，正常人读不了。
- 影响：只改创作助手展示层；识别结果浅底深字、用户气泡白底深字保持不变。
- 重新评估：侧栏改成浅色主题，或记忆卡需要独立浅色表面时。

## 2026-08-23：助手问答结构化信息用同一套字段排版

- 决策：识别结果、项目记忆、角色确认列表和候选稿字段共用 `AssistantInfoCard`：标签与值分行，已确认事实逐条展示，不再用分号拼成一段。
- 背景：确定角色信息一类回复里，文字、背景和间距挤在一起，长事实连成一段很难扫读。
- 影响：只改创作助手展示层；编号选项列表（如「方向1」）仍走普通 Markdown。
- 重新评估：模型开始用其他标记输出字段，或识别卡需要可编辑时。

## 2026-08-23：助手问答表面统一封装，底色和文字成套

- 决策：创作助手的面板、用户/助手气泡、识别结果卡、Markdown 共用 `ASSISTANT_CHAT_SURFACE`；助手气泡强制深底浅字，避免被 Sheet 的 `bg-background` 冲成浅底浅字。
- 背景：澄清需求正文几乎看不见，识别结果卡却可读；根因是浅色字和浅色底没有成套约束。
- 影响：只改展示层 token 与气泡封装，不改对话协议或回填数据。
- 重新评估：侧栏改浅色主题，或输入区也并入同一套表面时。

## 2026-08-23：策划助手按角色生成大纲，保存后回写项目正文

- 决策：角色设定助手的候选稿改为 `{ outline, characters }`。解析成功后左侧同时回填剧情大纲和角色；用户点保存才写入项目正文与已确认角色。旧的纯角色数组仍可解析。不再用「缺少导入正文」打断这条确认流。
- 背景：用户要求助手在这种情形下根据角色生成大纲，再像保存角色一样点保存反写，而不是直接报错。
- 影响：`parsePlanningDrafts`、大纲草稿本地恢复、`saveProject` 可带 `content` 覆盖。脚本/分镜默认路径不变。
- 重新评估：大纲需要分场结构或独立编剧步时。

## 2026-08-23：保存角色不依赖导入正文，生图错误区分本地配置和第三方

- 决策：角色确认写入工程时，剧情概要或已有角色即可保存，不再要求先导入小说正文。图片生成先检查本地图片服务配置；401/403/5xx 明确写成第三方图片服务错误，不再用「导入小说」这类文案冒充角色保存失败。
- 背景：用户点「保存角色」看到被理解成「大纲未保存」的拦截，角色却已出现在已确认列表；点「生成参考图」后无法判断是没配图片服务还是远端拒绝。
- 影响：`saveProject` 用 `project-save-guard`；`generateImage` 统一映射图片错误。对话保存仍只在 persist 成功后提示成功。
- 重新评估：图片服务改为异步任务协议，或工程保存改为静默自动保存时。

## 2026-08-23：AI 回填的角色草稿必须自动保存，重启后恢复

- 决策：助手回填或编辑角色草稿后，立即按项目写入本地草稿存储并在进入角色步时恢复。点「保存角色」仍只负责写入已确认角色和工程文件；未确认角色不再因重启丢失。手动表单点「保存」也直接写入工程。
- 背景：对话会话已按项目持久化，但 `draftCharacters` 只在页面内存里；用户重启后只剩空的「手动创建角色」表单。
- 影响：覆盖 2026-08-22「不自动保存工程除非用户点对话里的保存」对草稿层的部分；已确认角色仍需显式保存。不把草稿自动提升为已确认角色。
- 重新评估：草稿是否需要写入工程文件以便跨设备恢复，或脚本/分镜草稿是否采用同一自动保存。

## 2026-08-22：角色草稿先回填表单，对话内保存才写入项目

- 决策：角色候选稿解析成功后先回填左侧可编辑草稿（含外观、服饰）；对话里点「保存角色」才写入已确认角色。项目记忆保存不等于角色表单已填。
- 背景：用户确认「牛来」并保存记忆后，创建角色表单仍为空；旧流程要另点生成草稿和填充表单，且解析丢外观/服饰。
- 影响：覆盖助手面板旧 R3/R4 对「角色草稿预览」的禁止自动改表单；已确认角色仍需保存点击。脚本/分镜默认路径不变。
- 重新评估：脚本/分镜是否采用同一套预览+对话保存，或真实模型不主动 propose-candidate 时。

## 2026-08-22：多选技能保留各结果，文末只问一件事

- 重新评估：需要可点击下一步，或真实模型长期不遵守收口时。

## 2026-08-22：创作助手「思考过程」指智能体编排步骤

- 决策：用户可见的「思考过程」改为智能体本轮编排时间线（开始处理、应用点选技能、请求对话模型、整理回复、失败/取消），不是供应商推理分片，也不是模型输出的伪思维链。发送后清除输入框技能标签；无可见正文时保留步骤和说明。

- 重新评估：助手具备真实工具循环、需要把工具调用挂到同一时间线，或用户要求重新展示模型推理时。

## 2026-08-22：创作助手技能来源分层

## 2026-08-22：外部 API 接入暂不固化供应商

- 决策：在用户确认具体模型/视频厂商、endpoint、认证和代理模式前，不创建具体 Provider 实现。

## 2026-08-22：产品内助手采用 Novella 自有创作记忆协议

- 决策：不在用户侧运行或注入 `mattpocock/skills` 的开发代理技能；借鉴其需求澄清和共享词汇思想，在 `src/features/creative-assistant` 内维护项目级、用户确认后的创作记忆。
- 背景：外部技能面向代码代理，不是漫剧创作运行时；直接注入会增加无关上下文、提示词漂移和第三方文件维护风险。
- 影响：普通对话使用 `novella-state` 状态标记提出意图、事实、约束、待确认问题和术语；只有用户点击保存本轮记忆后才写入项目本地存储。候选稿请求关闭该协议并继续走现有确认回填。
- 重新评估：需要服务端持久化、多人协作记忆、联网工具调用，或项目知识图谱成为正式领域能力时。

## 2026-08-22：对话服务采用开发代理与生产原生传输的双轨策略

- 决策：开发期允许通过受限的 Vite 本地代理解决已配置对话服务的 CORS 预检问题；打包交付时不依赖 Vite 或 `127.0.0.1`，后续以 Tauri/Rust 原生 HTTP/SSE transport 作为根治方案。
- 背景：浏览器从 `http://127.0.0.1:1420` 直连远端服务时，已观察到 `OPTIONS` 预检被拒绝，导致实际 SSE 请求未发出。Codex 的网络请求不受浏览器同源策略约束，不能作为 WebView 可直连的证据。
- 影响：开发代理只能转发到启动时明确指定的 HTTPS 上游，页面不得控制代理目标；生产 transport 需要独立覆盖请求验证、超时、取消、事件清理、脱敏日志和真实服务契约测试。
- 重新评估：Tauri 原生 transport 完成并通过桌面端 SSE 验收后，或产品改为由本地 HTTP 服务承载前端时。

## 2026-08-22：桌面端切换到受控 Rust SSE，助手提供恢复操作

- 决策：Tauri runtime 优先调用 Rust `start_configured_dialogue`/`cancel_configured_dialogue`，通过 `novella://dialogue/*` 事件返回文本分片、完成和脱敏错误；Web runtime 保留 Vite 代理或直连。助手增加失败重试、单条消息删除和清空当前会话。
- 背景：浏览器 CORS 无法由打包应用中的 Vite 服务器解决；失败后用户需要在不丢失项目记忆的情况下恢复当前对话。
- 影响：桌面端需要 `reqwest` Rust 依赖和 IPC 事件契约；API key 只进入 native 请求内存，不写日志或事件。2026-08-22 已在本机完成 Rust 编译检查和 `pnpm tauri dev` 启动；真实密钥桌面 SSE 仍待用户在 Tauri 窗口验收。
- 重新评估：需要上传图片的 native multipart、视频/图像原生传输、重试策略扩展为指数退避，或远端供应商 SSE 契约发生变化时。
